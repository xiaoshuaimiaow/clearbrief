# ClearBrief 清晰启动

ClearBrief 是一个面向产品经理和项目负责人的 AI 项目启动工作台。它帮助用户把模糊需求、会议纪要、聊天记录或文档片段整理成可讨论、可评审、可分工的项目材料。

## 在线体验

**项目主页：** https://xiaoshuaimiaow.github.io/clearbrief/

Demo 和产品说明文档都可以从项目主页进入。

## 项目定位

很多项目并不是从一份完整 PRD 开始，而是从一句模糊需求开始，例如“公司文档太散，想做一个知识库”。真正影响推进效率的，往往不是没有文档，而是目标用户、范围边界、权限规则、验收标准和上线风险没有在早期被问清楚。

ClearBrief 的重点不是自动写一篇 PRD，而是把“需求澄清 -> 跨部门对齐 -> 竞品分析 -> 数据指标 -> PRD 生成 -> 需求评审”串成一条产品经理工作流。

## 核心功能

- 录入模糊需求、会议纪要、聊天记录或文档片段
- 识别项目类型、目标用户和当前信息缺口
- 按优先级生成追问问题，补齐目标、范围、指标、权限和兜底流程
- 生成包含跨部门对齐、竞品分析、数据指标和 SQL 口径的 PRD 草稿
- 输出需求评审报告，展示完整度评分和问题清单
- 按角色导出老板摘要、研发任务、设计 brief、运营材料、Kickoff 议程和管理员配置清单

## Demo 场景

企业内部文档分散，新员工和运营同事经常找不到会员政策、项目资料和流程制度。团队希望启动一个内部知识库改版项目，提高信息查找效率，减少重复沟通。

## 推荐体验路径

1. 打开项目主页。
2. 点击“打开可点击 Demo”。
3. 在输入页点击“开始分析”。
4. 在追问页选择任意一个问题并点击“确认回答”。
5. 生成完整 PRD，查看竞品分析、跨部门对齐、数据指标和 SQL 示例。
6. 进入评审报告，再到工作台查看不同角色的材料。

## 项目文件

- `index.html`：项目介绍页
- `demo.html`：可点击 Demo
- `prd.html`：产品说明文档
- `PRD.md`：Markdown 版产品说明
- `new-kickoff.html`、`kickoff-document.html`、`export-center.html`：页面参考稿

## 当前版本

当前版本是用于展示产品思路和交互流程的静态 Demo，已覆盖从模糊需求输入到 PRD 生成、跨部门对齐、竞品分析和数据分析的完整路径。后续可以继续接入真实 AI 后端，让用户输入自己的项目后实时生成分析结果。

## 真实 AI 接入思路

GitHub Pages 只适合放前端页面，不能直接保存大模型 API Key。真实 AI 版建议采用：

```text
GitHub Pages 前端 -> 后端接口 -> 大模型 API -> 结构化结果 -> 前端展示
```

第一阶段可以先做一次性返回：输入项目想法后生成需求缺口、追问问题、跨部门对齐、竞品分析、数据指标和 PRD 草稿。

第二阶段再做流式反馈：让页面逐步显示“识别项目类型”“生成追问问题”“整理 PRD 草稿”等过程，更接近真实 AI 产品体验。
