# ClearBrief 清晰启动

ClearBrief 是一个执行前信息确认与风险预审工具。

在正式设计、开发、打样、上线前，先判断这件事是否已经准备好执行。

在线体验：[https://xiaoshuaimiaow.github.io/clearbrief/](https://xiaoshuaimiaow.github.io/clearbrief/)

## 为什么做

很多团队管理执行过程，却没有管理开始执行的条件。

大多数返工不是执行错误，而是执行前就不该开始。

ClearBrief 的核心价值不是生成 PRD，而是提前暴露：

- 还缺哪些关键信息
- 哪些阻塞项会影响下一阶段
- 谁必须确认什么
- 当前能不能进入打样、上线、开发或制作
- 如果不能，下一步先补齐什么

## 当前 Demo 是什么

当前 Demo 是一个纯前端规则化交互原型。

用户可以：

1. 输入一句话描述准备推进的事项。
2. 选择快速案例，或让系统根据关键词匹配模板。
3. 点击“开始预审”。
4. 查看阻塞项、关键角色、成熟度评分和执行结论。
5. 点击阻塞项标记为已完成，观察成熟度和状态实时变化。

当前 Demo 支持四类示例：

- 足霜产品信息展示物料迭代
- 活动落地页上线预审
- 知识库改版预审
- AI Agent 需求预审

如果输入内容没有明显命中以上案例，系统会进入“通用事项执行前预审”，避免强行套用错误模板。

## 当前 Demo 不是

它不是：

- 真实 AI 系统
- 自动决策工具
- 企业级项目管理系统
- 完整 PRD 生成器
- 多人协作后端系统

它是：

- 前端规则化原型
- 用于验证执行前预审的产品流程
- 用于展示信息结构、阻塞项、角色确认和执行判断逻辑

高风险判断必须由责任角色人工确认。

## 模拟生成逻辑

Demo 会根据输入文字中的关键词匹配模板。

例如：

- 输入“包装、足霜、标签、打样、供应商”，匹配包装物料模板。
- 输入“活动、落地页、上线、优惠、埋点、法务”，匹配活动落地页模板。
- 输入“知识库、迁移、内容、搜索、标签”，匹配知识库模板。
- 输入“Agent、智能体、AI、兜底、权限、高风险”，匹配 AI Agent 模板。

匹配后生成：

- 阻塞项列表
- 风险等级
- 责任角色
- 处理建议
- 成熟度评分
- 当前执行状态
- 预审摘要

Demo 会显示匹配到的模板和命中依据，方便用户判断结果是否可信。

## 状态判断规则

- 只要存在未关闭的高风险阻塞项，状态为“不可执行”。
- 高风险关闭后，如仍有中风险未关闭，状态为“可预审”。
- 高风险和中风险关闭后，状态仍需人工确认，不能被系统当作最终拍板。

用户勾选阻塞项后，成熟度、关闭率、高风险数量和执行结论会同步变化。

## 操作演示指南

建议按这个顺序演示：

1. 打开首页，先讲产品洞察：团队常常管理执行过程，却没有管理开始执行的条件。
2. 进入 Demo，选择默认的“足霜产品信息展示物料迭代”。
3. 点击“开始预审”，观察 2 秒内出现高风险阻塞项和执行状态。
4. 解释为什么当前不可进入打样：成分文案、供应商边距、贴标位置未确认。
5. 勾选一个高风险阻塞项，展示成熟度和结论如何实时变化。
6. 切换到“活动落地页”或“AI Agent”案例，说明方法论可以迁移。
7. 最后讲产品边界：ClearBrief 不替代人工拍板，只提前暴露执行前问题。

## 面试讲述顺序

3 分钟版本：

1. 问题来源：来自材料科技创业项目实习中的包装 / 展示物料协作观察。
2. 产品洞察：很多返工不是执行中产生，而是执行前条件没有确认。
3. 产品定位：ClearBrief 不做 PRD 生成器，只做执行前信息确认与风险预审。
4. 核心流程：一句话输入 → 模板匹配 → 阻塞项生成 → 勾选关闭 → 状态更新。
5. 案例验证：默认案例是足霜物料，同时支持活动页、知识库、AI Agent。
6. 产品边界：不做项目管理，不做 AI 自动决策，不替责任角色拍板。
7. 未来规划：规则化原型 → LLM 信息提取 → 多角色确认 → 企业协作接入。

讲述重点：

- 我不是为了做一个“AI 工具”而做，而是从协作返工问题出发。
- 我主动砍掉了 PRD 生成、项目管理和自动决策，保留执行前判断。
- 多案例证明这是方法论，不是只服务包装物料的单点工具。
- 交互原型能演示完整闭环：输入、判断、阻塞、关闭、状态更新。
