# ClearBrief 清晰启动

ClearBrief 是一个执行前信息确认与风险预审工具。

在正式设计、开发、打样、上线前，先判断这件事是否已经准备好执行。

在线体验：[https://xiaoshuaimiaow.github.io/clearbrief/](https://xiaoshuaimiaow.github.io/clearbrief/)

## 为什么需要

很多团队管理执行过程，却没有管理开始执行的条件。

大多数返工不是执行错误，而是执行前就不该开始。

ClearBrief 关注的不是生成更多文档，而是提前暴露：

- 还缺哪些关键信息
- 哪些阻塞项会影响下一阶段
- 谁必须确认什么
- 当前能不能进入打样、上线、开发或制作
- 如果不能，下一步先补齐什么

## 产品如何工作

用户输入一句话描述准备推进的事项，系统根据关键词匹配预审模板，并生成：

- 阻塞项列表
- 风险等级
- 责任角色
- 处理建议
- 执行成熟度
- 当前执行状态
- 预审摘要

用户可以将阻塞项标记为“已确认”。阻塞项确认后，成熟度、确认率、高风险数量和执行结论会同步变化。

## 支持的事项类型

当前支持以下预审模板：

- 足霜产品信息展示物料迭代
- 活动落地页上线预审
- 知识库改版预审
- AI Agent 需求预审
- 通用事项执行前预审

如果输入内容没有明显命中具体模板，系统会进入“通用事项执行前预审”，避免强行套用错误场景。

## 状态判断规则

- 只要存在未确认的高风险阻塞项，状态为“不可执行”。
- 高风险确认后，如仍有中风险未确认，状态为“可预审”。
- 高风险和中风险都确认后，仍需责任角色做最终人工确认。

成熟度分数用于辅助判断，不作为自动决策依据。

## 产品边界

ClearBrief 不是：

- PRD 编写工具
- 项目管理工具
- AI 自动决策工具
- 企业审批流系统

ClearBrief 是：

- 执行前信息确认工具
- 风险阻塞项检查工具
- 责任角色确认提醒工具
- 下一步补齐动作整理工具

高风险判断必须由责任角色人工确认。

## 与现有工具的区别

| 工具 | 更适合做什么 | ClearBrief 关注什么 |
| --- | --- | --- |
| 飞书 | 记录、沟通、协作 | 执行前是否具备开始条件 |
| Notion | 文档沉淀和知识整理 | 事项推进前的缺口暴露 |
| Jira / TAPD | 任务拆解和执行跟踪 | 正式排期前的执行门槛 |
| ChatGPT | 内容生成和辅助分析 | 阻塞项、责任角色和人工确认链路 |

现有工具更多关注“如何执行”，ClearBrief 关注“是否已经准备好执行”。

## 本地使用

直接打开以下文件即可体验：

- `index.html`：产品首页
- `demo.html`：执行前预审工作台
- `prd.html`：产品说明页
- `PRD.md`：产品文档

当前版本为静态前端实现，不保存用户数据。
