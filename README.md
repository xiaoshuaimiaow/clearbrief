# ClearBrief 清晰启动

ClearBrief 是一个面向 0-3 年产品经理和项目推进者的执行前需求预审工具。它不定位为通用 PRD 生成器，而是帮助团队在正式投入设计、研发或打样前，先确认目标、约束、角色责任、风险和验收标准。

在线体验：[https://xiaoshuaimiaow.github.io/clearbrief/](https://xiaoshuaimiaow.github.io/clearbrief/)

## 一句话定位

ClearBrief 帮产品经理判断一个事项现在是“不能执行、可预讨论、可预审，还是可进入正式执行”。

## 产品背景

很多返工不是发生在执行阶段，而是发生在执行前没有确认清楚。比如产品信息展示物料迭代里，小尺寸包装和展示材料要同时承载产品名、成分说明、使用信息、品牌表达和贴标位置。产品、设计、品牌、供应商、展示材料之间如果没有先对齐信息优先级、尺寸边界和验收标准，正式制作和打印打样后就容易反复修改。

ClearBrief 从这个具体场景出发，抽象出一套执行前预审方法：

`需求预检 -> 信息缺口 -> 路径取舍 -> 执行门槛 -> 角色确认 -> 预审材料`

它解决的不是“帮用户多写一份文档”，而是让团队在投入成本前先看清楚：现在是否值得推进、还缺什么、谁必须确认、哪些风险会导致返工。

## 当前主案例

默认 Demo 使用“足霜产品信息展示物料迭代预审”：

- 小尺寸包装和展示物料需要承载产品名、成分说明、使用信息、品牌表达和贴标位置。
- 正式 Figma 制作和打印打样前，需要确认信息优先级、尺寸约束、打印边距、贴标位置和供应商样张标准。
- 建议路径是先做信息优先级表和低保真贴标验证，再进入 Figma 精修和打印打样。
- 每条关键判断区分来源：用户输入、已有物料、待人工确认和高风险复核。

## 核心能力

- 结构化输入业务问题、会议纪要、旧文档片段或物料要求。
- 梳理当前事项的目标、约束、相关角色和待确认缺口。
- 判断信息成熟度：不能执行、可预讨论、可预审、可进入正式执行。
- 对比不同推进路径的成本、收益、风险和适用时机。
- 标注判断来源，避免把预审结果直接当成最终结论。
- 输出预审材料、角色确认清单、阻塞项、验收标准和下一步动作。
- 保留人工确认、编辑和反馈回写，不替团队做最终决策。

## 文件说明

- `index.html`：产品首页，说明 ClearBrief 的定位、场景、流程和边界。
- `demo.html`：可点击 Demo，展示从问题输入到信息取舍、预审材料、执行前判断和角色化导出的流程。
- `prd.html`：公开产品说明页。
- `PRD.md`：Markdown 版产品说明。

## 当前体验路径

1. 打开首页，了解产品定位、适用场景和使用流程。
2. 进入在线 Demo，使用默认物料预审案例或输入自己的业务问题。
3. 点击“梳理当前事项”，查看问题类型、相关角色和待判断事项。
4. 在执行前判断页确认关键判断。
5. 查看路径对比、判断依据和暂不选择的原因。
6. 整理预审材料草稿，确认目标、约束、角色责任、风险和验收标准。
7. 进入执行前预审页，处理阻塞项、角色意见和供应商反馈。
8. 按需要导出老板摘要、供应商确认单、设计 Brief 或预审会议纪要。

## 产品边界

当前版本是前端可点击原型，用于展示执行前预审这条核心路径。它不会替代产品经理、设计、供应商或业务负责人做最终决策。

如果接入真实后端服务，还需要额外处理：

- 后端服务与 API 安全；
- 企业权限与敏感信息管理；
- 调用成本、失败兜底和日志审计；
- 人工复核与跨角色确认机制。
