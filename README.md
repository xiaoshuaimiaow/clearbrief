# ClearBrief 清晰启动

ClearBrief 是一个面向产品经理的方案预评审工具。
它帮助团队把已经感知到的业务问题，整理成可比较、可取舍、可落地的解决方案，而不是停留在“先写一份 PRD 再说”。

在线体验：[https://xiaoshuaimiaow.github.io/clearbrief/](https://xiaoshuaimiaow.github.io/clearbrief/)

## 项目定位

很多真实项目里，难点不是“需求完全不清楚”，而是大家已经知道哪里不顺，却还不确定应该怎么解。

例如：

- 新员工找不到资料，到底该先做文档治理、搜索优化，还是 AI 知识库助手
- 审批慢，到底是流程设计问题、权限问题，还是跨部门协作问题
- 活动转化差，到底该优化入口、激励机制，还是投放策略

ClearBrief 的重点不是自动生成一篇更长的文档，而是把下面这条产品经理工作链路串起来：

`问题诊断 -> 方案对比 -> MVP 收敛 -> PRD 输出 -> 方案评审 -> 角色化导出`

它更像一个项目启动阶段的判断辅助工具，帮助团队在正式排期前先把“为什么做、为什么这么做、首期做到哪里”想清楚。

## 核心能力

- 输入业务问题、会议纪要、聊天记录或零散材料
- 识别问题类型、受影响用户、当前待判断事项
- 生成关键判断问题，帮助 PM 明确根因、边界和验证口径
- 对比多种解决路径，展示成本、收益、风险和适用阶段
- 推荐首期方案，并明确暂不选择的原因与进入条件
- 输出包含问题定义、方案取舍、MVP 范围和验证指标的 PRD 草稿
- 在评审页判断方案是否值得进入下一阶段，而不只是检查材料齐不齐
- 导出完整 PRD、评审纪要、老板摘要、研发任务清单、设计 Brief 和数据分析口径

## 页面说明

- `index.html`：作品集首页，强调项目背景、产品判断和设计取舍
- `demo.html`：可点击 Demo，展示问题诊断到方案评审的完整流程
- `prd.html`：公开产品说明页
- `PRD.md`：Markdown 版产品说明 / PRD

## 当前体验路径

1. 打开首页，了解项目定位和产品主线
2. 进入 Demo，输入一个业务问题或选择内置案例
3. 点击“开始分析”，查看问题类型、受影响用户和待判断事项
4. 在“问题诊断”页确认关键判断
5. 查看系统生成的方案对比与推荐理由
6. 生成完整 PRD，确认问题定义、方案取舍和 MVP 范围
7. 进入“方案评审与推进决策”，判断是否值得进入下一阶段
8. 在工作台导出不同角色需要的材料

## 默认案例

当前 Demo 默认采用“内部知识库资料难找”的场景。

这个案例刻意不是“需求很模糊”，而是“问题已经出现，但方案还没定”：

- 业务方知道新人和跨部门同事找资料效率低
- 团队知道要改善信息获取体验
- 但首期到底该先做文档治理、搜索与标签优化，还是 AI 问答助手，存在明显取舍

这让 ClearBrief 更贴近真实 PM 工作，而不是停留在“把一句话扩写成文档”。

## 产品亮点

- 不是默认“上 AI”，而是先比较文档治理、工具优化和 AI 方案的适配性
- 不只展示理想流程，也覆盖真实项目里最重要的方案判断与排期前验证
- 评审模块更贴近工作现场：判断方案是否值得推进，而不是只做会前材料检查
- 输出材料强调可继续编辑和协作，而不是把 AI 结果当成最终答案

## 使用边界

当前版本是前端可点击原型，用于展示完整产品思路和交互路径。

如果接入真实 AI 与企业数据，还需要额外处理：

- 后端模型调用与 API 安全
- 企业权限与敏感信息管理
- 调用成本、失败兜底和日志审计
- 人工复核与跨角色确认机制

ClearBrief 不替代业务决策、技术评估、法务审核或财务审批。它的价值是在项目进入正式排期前，帮助团队更早形成更好的判断。

## 后续可扩展

- 接入真实大模型，支持动态生成判断问题、方案建议和 PRD 草稿
- 接入企业文档、会议纪要和协作工具，减少手动整理成本
- 增加历史项目管理、评审记录沉淀和团队权限控制
- 补充更多高频案例，如审批流程、活动转化、客服分流、数据看板等
- 继续优化 Demo 的信息密度和引导方式，让体验更轻、更顺
