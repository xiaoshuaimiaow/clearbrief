ClearBrief 清晰启动 - 产品说明

一个面向产品经理的方案预评审工具，帮助团队把业务问题变成可比较、可取舍、可落地的解决方案。

1. 项目概述

ClearBrief 面向 0-3 年产品经理、项目负责人和需要推动跨部门协作的业务同学。它支持输入业务问题、会议纪要、聊天记录或零散文档片段，并将其整理成结构化的项目启动材料。

当前版本是可点击原型，重点展示从输入业务问题，到问题诊断、方案对比、MVP 收敛、PRD 输出、方案评审和角色化导出的完整路径。

2. 背景与机会

很多真实项目里，难点不是“没人写 PRD”，而是大家已经知道哪里有问题，却还没判断清楚该怎么解。团队容易直接跳到某个功能方案，却没有认真比较其他路径的成本、收益和风险。

如果这些判断拖到评审会甚至开发阶段才暴露，就会导致重复沟通、范围膨胀、排期反复和返工风险。ClearBrief 希望把方案判断前置，让团队在项目启动阶段就先形成比较清晰的决策依据。

3. 目标用户

  • 核心用户：0-3 年产品经理，需要把业务问题转成可推动的方案和启动材料。
  • 次级用户：项目负责人、运营负责人、业务负责人，需要更快完成方案对齐和首期收敛。
  • 协作用户：研发、设计、测试、数据、业务、合规等角色，需要看到与自己相关的边界、风险和依赖。

4. 产品目标

  • 识别问题类型、受影响用户和当前待判断事项。
  • 帮助 PM 对比多种解决路径，而不是直接跳到单一方案。
  • 帮助团队收敛首期 MVP，明确本期做什么、不做什么。
  • 输出可进入评审的 PRD 草稿和方案结论。
  • 让评审围绕“这个方案是否值得推进”展开，而不是只检查材料完整度。

5. 核心流程

  1. 用户输入业务问题、会议纪要、聊天记录或零散文档片段。
  2. 系统识别问题类型、受影响用户和当前待判断事项。
  3. 系统生成关键判断问题，帮助用户确认根因、边界和成功标准。
  4. 页面展示多种解决路径，比较成本、收益、风险和适用阶段。
  5. 系统输出推荐方案，并说明暂不选择的原因与进入条件。
  6. 用户生成完整 PRD，确认问题定义、方案取舍和 MVP 范围。
  7. 用户进入“方案评审与推进决策”，判断是否适合进入下一阶段。
  8. 工作台按角色导出材料，用于老板同步、研发拆解、设计协作和数据跟进。

6. MVP 范围

输入与案例切换

用户可以输入自己的业务问题，也可以切换内置案例。当前案例覆盖知识库、活动、数据看板、客服分流、课程体验、审批流程等场景。

问题诊断

系统根据输入内容判断问题类型、受影响用户、当前已知信息和仍待确认的关键事项，帮助用户先把问题拆清楚。

关键判断确认

系统按优先级生成关键判断问题。用户确认后，结构化信息卡、方案推荐和 PRD 内容同步更新。

方案对比与推荐

系统展示多种解决路径，并从成本、收益、风险、依赖和适用阶段等维度进行对比。默认知识库案例会展示文档治理、搜索与标签优化、AI 知识库助手三种路径。

MVP 收敛

系统帮助用户明确本期优先做什么、本期明确不做什么，以及进入下一阶段前必须验证什么。

PRD 生成

PRD 包含项目背景、问题定义、目标用户、已确认判断、方案对比与推荐、MVP 范围、核心流程、跨部门对齐、数据指标、风险与兜底和验收标准。

7. 方案评审

评审模块关注的是方案是否值得推进，而不是文档是否齐全。

模块作用
问题价值判断确认这是不是值得优先解决的问题，是否影响核心用户和关键业务指标。
方案取舍判断确认推荐方案是否站得住脚，是否说明了为什么不选其他路径。
MVP 边界判断确认首期范围是否收敛，是否明确了本期不做什么。
风险与依赖检查确认权限、兜底、数据、协作依赖和实现风险是否可控。
推进结论输出输出是否进入下一阶段，以及排期前仍需验证的事项。

推进状态流转

  • 暂缓评审：方案依据不足，建议先补根因、推荐理由或验证指标。
  • 先补方案依据：材料能讨论，但还不足以支撑推进决策。
  • 可评审：已有较完整方案判断，可以进入跨角色讨论。
  • 可进入下一阶段：方案、边界和验证口径基本明确，可进入排期或进一步技术评估。

8. 数据指标

效率指标

  • 从输入问题到形成首轮方案结论的时长
  • 评审材料准备时长
  • 跨部门确认轮次

质量指标

  • 评审前发现的问题数
  • 方案变更次数
  • MVP 边界调整次数
  • PRD 二次修改比例

协作指标

  • 角色意见关闭率
  • 阻塞问题关闭率
  • 评审后返工次数

9. 风险与边界

ClearBrief 更适合作为项目启动阶段的方案预评审助手，而不是最终决策者。它可以帮助团队更早形成判断，但不能替代业务优先级决策、技术评估、法务审核、财务审批和数据安全判断。

如果未来接入真实大模型和企业数据，还需要额外处理后端调用、安全控制、日志审计、失败兜底和人工复核机制。

10. 项目价值

ClearBrief 的价值不在于生成一份更长的文档，而在于帮助团队更早做对判断。它把问题诊断、方案对比、MVP 收敛、PRD 输出、方案评审和跨部门导出放在同一条流程里，让产品经理展示的不只是“会写文档”，而是“能定义问题、比较方案、控制范围、推动决策”。
