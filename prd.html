ClearBrief 清晰启动 - 产品说明

一个面向 0-3 年产品经理的需求评审前预检工具，帮助用户把模糊需求变成可讨论、可评审、可分工的项目材料。

1. 项目概述

ClearBrief 优先面向 0-3 年产品经理和临时承担项目 owner 的同学。它支持输入模糊需求、会议纪要、聊天记录或文档片段，并将其整理为结构化的项目启动材料。

当前版本是可点击原型，重点展示从输入项目想法到生成 PRD、进入评审、记录研发反馈和导出材料的完整路径。

2. 背景与问题

很多项目不是从完整 PRD 开始，而是从一句模糊需求开始。真正拖慢项目推进的，往往不是没人写文档，而是目标用户、范围边界、权限规则、异常流程、数据指标和验收标准没有在早期被问清楚。

如果这些问题到评审会甚至开发阶段才暴露，会导致重复沟通、范围变更和排期风险。ClearBrief 希望把这些问题前置，让团队在项目启动阶段就能看到缺口。

3. 目标用户

  • 核心用户：0-3 年产品经理，需要把模糊需求转化为 PRD、评审材料和跨部门任务。
  • 次级用户：项目 owner 或运营负责人，需要更快补齐业务目标、活动范围、数据指标和复盘口径。
  • 协作用户：研发、设计、测试、数据成员，需要从同一份材料中看到与自己相关的边界、依赖和验收标准。

4. 产品目标

  • 识别模糊需求中的项目类型、目标用户和信息缺口。
  • 通过追问机制补齐目标、范围、指标、权限和异常流程。
  • 生成结构化 PRD，降低项目启动材料准备成本。
  • 输出需求评审结论，让关键风险在正式评审前暴露。
  • 支持按角色导出材料，减少跨部门沟通成本。

5. 核心流程

  1. 用户输入项目想法、会议纪要或文档片段。
  2. 系统识别项目类型、目标用户和当前缺失信息。
  3. 系统生成高优先级追问，用户确认关键回答。
  4. 已确认回答进入结构化信息卡。
  5. 系统生成 PRD、竞品分析、数据指标和 SQL 示例。
  6. 用户进入需求评审，检查会前材料、角色意见、阻塞项和研发反馈。
  7. 工作台按角色导出老板摘要、研发任务、设计 Brief、评审会议纪要和数据分析口径。

6. MVP 范围

输入与案例切换

用户可以输入自己的项目，也可以切换内置案例。案例覆盖内部知识库、活动、数据看板、客服分流、课程体验、审批流程等场景。

信息缺口识别

系统根据输入判断项目类型、目标用户、核心问题和缺失信息。缺失项包括目标、范围、权限、指标、预算、异常流程和跨部门依赖。

追问补齐

系统按优先级生成追问问题。用户确认回答后，结构化信息卡、PRD 和后续评审材料会同步更新。

PRD 生成

PRD 包含项目背景、问题定义、目标用户、产品目标、已确认结论、MVP 范围、核心流程、跨部门对齐、竞品分析、数据指标、数据口径、风险兜底和验收标准。

7. 评审模块

评审模块不是简单打分，而是关注项目是否可以进入下一阶段。

模块作用
会前材料检查确认背景目标、MVP 范围、流程、权限、数据验收和依赖排期是否齐全。
角色意见确认记录研发、设计、测试、数据、业务、合规等角色是否已确认或仍有疑问。
评审待办清单明确阻塞项、非阻塞项、影响、建议动作、Owner 和处理状态。
研发反馈回写把评审会或协作工具里的研发反馈整理后决定是否写回 PRD。
会议纪要导出导出评审结论、材料缺口、角色意见、研发反馈和会后动作。

评审状态流转

真实工作里，评审不是简单“打分高就通过”。ClearBrief 用状态流转表达项目是否能进入下一阶段：

  • 会前待补齐：材料缺口较多，不建议直接拉跨部门评审。
  • 待复审：存在阻塞项或关键角色疑问，需要补齐后再确认。
  • 带条件通过：阻塞项已处理，剩余非阻塞问题可以跟随原型或技术预研继续推进。
  • 通过：材料、角色意见和评审待办均已关闭，可以进入开发排期评估。

8. 数据指标

效率指标

  • 评审材料准备时长
  • 需求信息补齐耗时
  • 跨部门确认轮次

质量指标

  • 评审前发现的问题数
  • 评审缺口发现率
  • 验收标准覆盖率
  • PRD 二次修改比例

协作指标

  • 角色意见关闭率
  • 研发阻塞问题数量
  • 评审后返工次数

9. 风险与边界

ClearBrief 更适合作为评审前预检助手，而不是最终评审人。它可以帮助团队更早发现问题，但不能替代业务决策、技术评估、法务审核、财务审批和数据安全判断。

当前公开版本是前端可点击原型，模拟 AI 分析流程。生产环境如果接入大模型，需要通过后端接口调用模型，并额外处理企业权限、敏感信息、调用成本、失败兜底、日志审计和人工复核机制。

10. 项目价值

ClearBrief 的价值不在于生成一份更长的文档，而在于让团队更早问对问题。它把需求澄清、PRD 生成、评审预检、研发反馈和跨部门材料导出放在同一条流程里，帮助产品经理更稳定地完成项目启动工作。
